# Implementation Decision Log (autonomous decisions)

> Per owner build directive §2: non-critical implementation decisions are made autonomously,
> documented here, and work continues. Decisions follow the locked Master Specification,
> prefer the simplest robust implementation, preserve $0 cost and future extensibility,
> and are only escalated if genuinely blocking.

| ID | Date | Decision | Rationale |
|---|---|---|---|
| IL-001 | 2026-09-09 | **Dual-track M0 validation**: Python reference engine (executed + fully tested in this environment) + canonical C# `DesiLudo3D.Rules` (netstandard2.1, zero deps) locked together by a shared line-based conformance-vector format. | No C# compiler/runtime obtainable in the AI build sandbox (Microsoft/Debian CDNs blocked; GitHub release assets carry no SDK binaries; NuGet unreachable). PyPI + GitHub reachable. The vectors make any C#-vs-reference divergence a loud test failure rather than silent drift. The Python engine additionally serves as fuzz oracle, future server-port reference, and event-log/AI-dataset generator. |
| IL-002 | 2026-09-09 | **Blockade semantics (D4)**: a blockade = 2+ tokens of one seat on any of the 52 loop cells (safe or star cells included), blocking all OTHER seats' passage AND landing; the owning seat passes and stacks freely; home columns can never be blockaded; with the toggle OFF, stacks are purely visual and never block. | Uniform, classic, simplest-to-explain rule; owner-passes-own is the common desi-house interpretation; uniformity avoids special-casing safe cells. |
| IL-003 | 2026-09-09 | **D2 void scope**: the third consecutive six voids the ENTIRE turn — a turn-start snapshot (token progresses + finished order; left-flags are monotonic and never restored) is restored, and a `TurnVoided` event carrying the restored data is emitted so presentation can resync. | Spec D2 text says "all three rolls are void" — implemented literally via event-sourced snapshot restore (cheap: state is tiny). |
| IL-004 | 2026-09-09 | **A 6 always grants its extra roll**, even when the 6 yields no legal move (fully blocked / all overshoot). The D2 third-six void bounds any chain. | The extra roll is the intrinsic reward of the face; avoids the ambiguity of conditional grants. Rare edge; both readings exist in the wild — this one is simplest and never feels like a stolen roll. |
| IL-005 | 2026-09-09 | **No extra roll for finishing a token** — extra rolls come only from a 6 (D2 context) and a capture (D3). | Spec lists exactly these two; adding finish-extra would change game balance silently. |
| IL-006 | 2026-09-09 | **R1 clip acquisition = Android system photo/video picker + in-app trim/tag; zero camera code in V1.** | Owner amendment A1 forbids all camera machinery (permission flow, recording, encoding, sharing, cooldowns, privacy UI) while A1/R1 keep prerecorded clips in V1. Picker import is the only camera-free acquisition path and was already the spec's no-permission path for photos. |
| IL-007 | 2026-09-09 | Engine supports **3-player matches** (config-level; UI may expose later). | Zero cost, forward-compatible, common request for family play; modes stay 2p/4p in V1 UI per spec. |
| IL-008 | 2026-09-09 | **Line-based text codecs** (`docs/RULES-FORMAT.md`) for state, command log, event log, and conformance vectors. | Parser-trivial in both C# and Python; human-readable in git diffs; deterministic byte-for-byte round-trips; zero dependencies. |
| IL-009 | 2026-09-09 | **Turn snapshot is part of serialized state and of the state hash.** | A resumed mid-turn match must still void correctly on a third six; two board-identical states with different turn history are NOT logically identical. |
| IL-010 | 2026-09-09 | **Vector trust chain**: hand-written tests encode independently-computed ground truth (cell math done by hand) → they validate the Python engine → only then does the engine generate random/full-match conformance vectors for the C# port. | Vectors are only as trustworthy as their generator; the trust chain starts from human-verified expectations, not from the implementation itself. |
| IL-011 | 2026-09-09 | Standings tie-break for unfinished players: tokens-home desc → non-leavers above leavers → seat order in the match config. | Deterministic, matches spec ("finish order → tokens home"); a quitter never outranks a stayer on a tie. |
| IL-012 | 2026-09-09 | Commit–reveal combine: `SHA-256(seed₀‖seed₁‖…)` in seat order, first 4 bytes big-endian → uint32 → `v % 6 + 1` (2³² mod 6 bias ≈ 9×10⁻¹⁰ — negligible, documented). Multi-party (all seats contribute) for 3–4 player rooms. | Unbiased enough by any practical standard; order is unambiguous; every player can verify post-hoc. |
| IL-013 | 2026-09-09 | **M0 dual-track delivered**: Python reference engine fully validated (57 tests, hand-computed ground truth) → generated 14 conformance vectors → canonical C# `DesiLudo3D.Rules` authored as a faithful mirror (netstandard2.1, zero deps) with a vector-consuming test suite. C# compile validation deferred to any .NET SDK 8+ machine (`dotnet run --project tests/DesiLudo3D.Rules.Tests`) — one command closes M0. | Environment cannot obtain a C# toolchain (IL-001). The vectors make the C# port's correctness binary-verifiable the moment it compiles; the rules logic itself is already validated via the reference implementation. |
| IL-014 | 2026-09-09 | Rules change protocol locked: reference + hand tests → green → regenerate vectors → mirror in C# → C# vector suite green → new IL entry. Never edit one side alone. | Keeps the two implementations permanently conformance-locked (docs/BUILD.md). |
| IL-015 | 2026-09-09 | C# engine mirrors Python event/state text byte-identically, including the canonical FNV-1a hash string (flags, snapshot inclusion, seat-name casing, csv orders). | The conformance vectors compare event lines, state text and hash exactly; any textual divergence is a loud failure, not silent drift. |
| IL-016 | 2026-09-09 | **No hand-authored Unity YAML.** The Unity project ships only `Packages/manifest.json` + `ProjectSettings/ProjectVersion.txt` (both trivially safe formats); PlayerSettings, the scene, and pipeline assignment are configured by `ProjectSetupWizard` via Unity's own editor APIs (`Tools > DesiLudo3D` menu). | Hand-writing Unity serialized YAML (scene/ProjectSettings/URP assets) is the single largest corruption risk when the editor cannot verify the result; editor-API configuration cannot produce malformed serialization. |
| IL-017 | 2026-09-09 | `GrayBoxInput` compiles under ANY Active Input Handling (legacy / new / both) using the engine's own `ENABLE_INPUT_SYSTEM` / `ENABLE_LEGACY_INPUT_MANAGER` defines; the wizard additionally tries to set "Both" via the internal setter and logs the manual instruction if unavailable. | Makes first-open behaviour deterministic regardless of the project's input config; no doc-dependent input setup. |
| IL-018 | 2026-09-09 | **Board map validated before mirroring:** the 15×15 coordinate table lives in Python (`ludo/boardmap.py`) with a self-check (52 unique cells, spacing 13, entrances adjacent to runways, base slots in quadrants). The check initially caught that the classic track makes **4 diagonal corner hops** at the inner cross corners — now documented and asserted explicitly; the C# `BoardGridMap` mirrors the validated table. | Hand-drawn coordinate tables are error-prone; the validated Python table is the single source of truth the C# mirrors. |
| IL-019 | 2026-09-09 | Gray-box materials pick URP Lit vs built-in Standard at runtime based on the active render pipeline. | The project renders correctly even before the URP asset is created/assigned (wizard step 4), so first-open never shows a pink board. |
| IL-020 | 2026-09-09 | The canonical rules library is synced into `unity/Assets/_Core/Rules/` by `tools/sync_rules_to_unity.py` (hash-verified, `--check` mode for CI). That folder is never edited by hand. | Unity cannot reference sources outside Assets; the sync script prevents the copy from silently drifting from `src/` (extends IL-014). |
| IL-021 | 2026-09-09 | **M1 scene is fully procedural** — `GameBootstrap` builds board/camera/light/dice/HUD in code; the repo contains no binary Unity assets until the M3 art pass. | Keeps the repo text-only (reviewable, mergeable) and makes the setup wizard the only authored scene step. |
| IL-022 | 2026-09-09 | `MatchRunner.Save()/Load()` serializes state + command log + event log in one text blob and verifies integrity by replaying the log and comparing state hashes on load. | Save/resume (spec §4.3) must survive process death AND tampering; hash-checked replay gives both for free on top of the event-sourced log. |
